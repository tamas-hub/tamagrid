# TamaGrid Code of Conduct

## Our commitment

We want TamaGrid to be a welcoming, practical, and safe open-source project. Contributors, maintainers, and users are expected to treat one another with respect regardless of experience, identity, background, disability, language, or viewpoint.

## Expected behavior

- Discuss the work, not the worth of the person doing it.
- Give specific, actionable feedback and accept correction in good faith.
- Respect privacy. Do not publish credentials, personal information, private repository data, or unredacted task output.
- Keep issues and pull requests focused on TamaGrid and its documented scope.
- Prioritize user safety when discussing command execution, approvals, sandboxing, and release artifacts.

## Unacceptable behavior

- Harassment, threats, discrimination, sexualized attention, or sustained personal attacks.
- Trolling, deliberate disruption, impersonation, or knowingly misleading security claims.
- Publishing another person's private information or secrets without explicit permission.
- Pressuring maintainers or users to weaken platform protections, bypass approvals, or execute unverified binaries.

## Enforcement

Maintainers may edit or remove content, close contributions, temporarily restrict participation, or permanently ban participants when behavior threatens the community or project. Enforcement decisions should be proportionate, documented privately where possible, and avoid exposing reporters or affected people.

For a security vulnerability, use the private process in [SECURITY.md](SECURITY.md). For a conduct concern that should not be public, do not post the sensitive details in an issue. Use a private maintainer contact published by the repository; if none is available yet, ask for a private contact in a detail-free issue and use GitHub's abuse-reporting tools when appropriate.

This code applies in TamaGrid repositories, issue trackers, pull requests, release discussions, and other spaces where someone represents the project.
